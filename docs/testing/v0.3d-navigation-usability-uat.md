# v0.3D Navigation Usability UAT

## UAT finding

Browser validation identified two shell usability requirements:

1. users need more workspace width without losing navigation access;
2. compact navigation icons need their item names discoverable on hover.

## Implemented behavior

- Desktop/tablet primary navigation can be collapsed and expanded explicitly.
- The preference is retained in browser local storage when storage is available.
- A first visit at 980px or below defaults to the compact rail.
- A first visit above 980px defaults to the expanded navigation.
- Collapsed links retain `aria-label` values and native hover titles.
- The collapse/expand control has an explicit accessible label, focus state,
  `aria-expanded`, and hover title.
- The compact rail is 86px wide; the released width returns to the workspace.
- At 700px and below the existing mobile navigation remains authoritative.

## Browser validation

Before merging PR #11 verify:

- collapse reduces the sidebar to the icon rail;
- expand restores section and item labels;
- refreshing preserves the chosen state;
- hovering each collapsed icon exposes its navigation name;
- keyboard focus can reach the toggle and each navigation link;
- active-route styling remains visible in both states;
- no workspace content overlaps the sidebar;
- at <=700px the sidebar remains hidden and mobile navigation still works.

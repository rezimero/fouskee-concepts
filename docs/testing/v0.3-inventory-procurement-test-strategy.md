# v0.3 Inventory / Procurement Test Strategy

## Test database

Continue using MySQL `fouskee_concepts_test`.

Do not switch these tests to SQLite because locking, decimal behavior, foreign keys, and trigger behavior matter to this domain.

## 0.3A minimum feature coverage

### Location security
- location creation is organization-scoped;
- user cannot read another organization's locations.

### Receipt posting
- receipt increases base-unit on-hand;
- package quantity converts using the transaction snapshot;
- audit event is recorded.

### Transfer
- source decreases;
- destination increases;
- net organization quantity is conserved;
- both legs commit atomically.

### No-negative-stock
- issue/transfer beyond available stock is rejected;
- no ledger rows are left after rejection;
- projection remains unchanged.

### Idempotency
- same idempotency key cannot post twice;
- retry returns deterministic result or explicit conflict per contract.

### Reversal
- reversal exactly negates original quantity/value;
- original movement remains unchanged;
- second unauthorized reversal is rejected.

### Projection rebuild
- balance projection can be reconstructed from movement lines;
- reconciliation reports zero difference after normal posting.

### Organization isolation
- movement/balance queries never leak another organization.

### Privileged actions
- adjustment requires permission and business reason;
- negative override requires explicit permission and reason;
- suspended users remain blocked;
- Superadmin remains audited.

## Decimal coverage

Use non-integer package conversions in tests to prevent accidental integer or floating-point assumptions.

## Concurrency coverage

Add MySQL-specific concurrency tests around two simultaneous commands consuming the same stock balance.

The pass criterion is that row locking and validation permit only the stock that actually exists.

## Procurement minimum coverage

- cannot approve own PO when maker-checker applies;
- partial receipt updates procurement state correctly;
- over-receipt tolerance produces an exception;
- posted receipt creates one inventory movement;
- duplicate supplier invoice is rejected;
- exact three-way match returns matched;
- quantity/price mismatch returns exception;
- exception approval records actor and reason;
- reversal leaves original receipt evidence intact.

## Database immutability coverage

When inventory ledger hardening triggers are introduced, test both ORM and direct SQL UPDATE/DELETE rejection, following the audit-ledger pattern.

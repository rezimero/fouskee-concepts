# Handover v0.2B draft — Authentication and security

## Increment
0.2B1: backend SPA authentication, MFA enforcement, security sessions, and typed
frontend authentication client.

## Authentication stack
- Laravel Sanctum: stateful first-party SPA authentication.
- Laravel Fortify: headless login and TOTP two-factor flows.
- React/Vite: Axios client with credentials and XSRF support.
- No public registration routes are enabled.

## Security behavior
- Login is limited to active users.
- Login and TOTP challenge attempts are rate limited.
- Successful login, failed login, logout, and session revocation are audited.
- Failed-login audit records hash the submitted email instead of recording it.
- `mfa_required` forces confirmed TOTP before protected business/security routes.
- `/api/v1/me` remains available after login so the SPA can discover required MFA.
- Session management returns HMAC references, not raw Laravel session IDs.
- Session revocation requires the current password and a privileged-action reason.

## Local development
Backend: `http://localhost:8000`
Frontend: `http://localhost:5173`

Use `localhost` consistently in the browser. The setup script configures Sanctum
stateful domains, the Laravel frontend origin, and the Vite API URL.

## Regression coverage
- active users can authenticate;
- suspended users cannot authenticate;
- public registration is absent;
- unauthenticated identity access is rejected;
- MFA-required users are blocked from privileged routes until enrollment;
- Superadmin permission bypass is preserved;
- privileged-action reasons are mandatory;
- another server-side session can be listed and revoked with password confirmation.

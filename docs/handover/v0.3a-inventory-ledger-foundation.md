# Handover — v0.3A Inventory Ledger Foundation

## Scope

v0.3A introduces the first inventory runtime foundation:

- organization-scoped inventory locations;
- optional lot-ready schema;
- immutable movement headers and lines;
- rebuildable inventory balance projection;
- reservations;
- idempotent posting;
- no-negative-stock enforcement;
- receipts;
- atomic transfers;
- controlled adjustments;
- reversals;
- package conversion snapshots;
- inventory permissions and audit events.

No inventory UI is introduced in 0.3A.

## Source of truth

Posted `inventory_movement_lines` are authoritative for physical stock.

`inventory_balances` is a derived operational projection and may be rebuilt.

## Sensitive actions

Adjustments and reversals require both a named permission and
`X-Privileged-Reason`.

## Database hardening

Application models reject movement/line update and delete.

Privileged MySQL trigger installation is intentionally separate:

`scripts/database/harden-inventory-ledger.ps1`

The runtime application DB account must not be granted TRIGGER/SUPER rights.

## Deferred

- negative-stock break-glass override;
- backdate override;
- stock-count workflow;
- lot UI;
- procurement documents and three-way matching;
- inventory frontend workspace;
- full inventory-value/weighted-average projection posting.

The ledger schema captures cost evidence so valuation can be completed without
changing historical quantities.

## Packaging default hardening

A MySQL generated-column uniqueness guard now enforces at most one default sale
package and one default purchase package per product.

The product request also rejects conflicting defaults before database insertion.

# v0.4B1 — Sales Inventory Reservations

Delivered:
- approved-order-only reservation;
- explicit active fulfillment location;
- transit-location rejection;
- Sales-line aggregation in base units;
- deterministic lot-aware allocation;
- reuse of Inventory balance locks and availability rules;
- owned-reservation create/release boundary;
- idempotent repeat reservation;
- atomic rollback on insufficient location stock;
- privileged-reason release;
- Sales and Inventory audit events;
- MySQL immutability for reservation identity and deletion;
- organization-scoped reservation summary API.

API:
- `GET /api/v1/sales/orders/{id}/reservation`
- `POST /api/v1/sales/orders/{id}/reservation`
- `POST /api/v1/sales/orders/{id}/reservation/release`

Reserve requires `inventory.reserve`; release also requires the privileged
reason middleware.

Deferred:
- pick lists;
- reservation consumption;
- outbound inventory posting;
- split-location fulfillment;
- backorders/substitutions;
- delivery routing;
- invoice/payment coupling;
- POS cashier workflow.

The next slice should add controlled picking/dispatch and reservation
consumption without allowing Sales to write inventory balances directly.

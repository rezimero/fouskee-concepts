# v0.3D Inventory / Procurement Workspace — Implementation Record

## Baseline

`develop @ 90e26ae`

The milestone consumes the inventory and procurement APIs delivered by
v0.3A-v0.3C. It introduces no database migration and does not modify privileged
database triggers.

## Delivered workspaces

### Command overview

The dashboard now summarizes:

- inventory value;
- stock transfers in transit;
- approval / exception control queue;
- procurement-eligible supplier invoices.

Metrics are loaded only for domains the authenticated user may view.

### Stock intelligence

The workspace combines:

- on-hand quantity;
- reservation quantity;
- available quantity;
- lot scope;
- perpetual weighted-average cost;
- inventory value;
- recent immutable movement evidence.

### Stock counts

Staff can:

- capture physical count evidence;
- select explicit lot scope;
- submit a count;
- approve or reject material variance when authorized.

Privileged actions collect a business reason. Server maker-checker remains
authoritative.

### Controlled transfers

Staff can:

- create a transfer;
- dispatch source stock into transit;
- confirm destination receipt;
- cancel an eligible transfer with a privileged reason.

The UI exposes the source, transit, destination, status, and quantity evidence.

### Purchase orders

Staff can:

- create a draft from active supplier/product master data;
- submit frozen terms;
- approve or reject when authorized;
- cancel eligible orders with a reason.

### Receiving desk

The normal staff receiving path records physical receipt only against approved
or partially received purchase orders.

It supports:

- receiving location;
- physical receipt timestamp;
- lot/batch and expiry evidence;
- partial quantities;
- optional privileged backdate reason;
- receiving-exception approval/rejection;
- posted-receipt reversal.

### Supplier invoices

Staff can:

- record a supplier invoice against purchase-order lines;
- retain supplier-stated tax evidence;
- run a three-way match;
- inspect quantity/price/amount exception codes;
- approve or reject current match exceptions when authorized.

The screen distinguishes procurement eligibility from payment execution.

## Shell changes

The desktop sidebar is grouped into:

- Command;
- Commerce;
- Inventory;
- Procurement;
- Security.

The existing mobile navigation remains horizontally scrollable and
permission-filtered.

## Shared UI additions

v0.3D introduces reusable operational components for:

- status badges;
- control notices;
- metrics;
- record rows;
- evidence facts;
- privileged-action reasons;
- inventory tables/timeline;
- document details;
- product/package/lot line editors.

The existing `Sheet` component gains an optional wide mode without changing
existing master-data sheet behavior.

## Deferred

- server-side autocomplete/search for catalogs above 100 records;
- dedicated direct inventory adjustment workspace;
- reservation management workspace;
- procurement policy editor;
- inventory policy editor;
- command palette;
- frontend automated component/e2e framework;
- dark mode;
- sales/POS workflows.

These remain candidates for later milestones and should not be implemented by
duplicating domain rules in React.
